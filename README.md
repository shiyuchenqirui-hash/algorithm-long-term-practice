# 算法长期练习

## 这份仓库的用途

这是一个面向长期维护的面试算法练习仓库，用来保存练习策略、阶段进展和必要的代码记录。

它不是短期刷题打卡项目。核心目标是：用低频但持续的练习掌握高频母题，保持基本手感，避免未来再次求职时因算法题准备不足而被动。

## 当前阶段

已练习与待补齐的题型见 [练习进展](PROGRESS.md)。公开仓库记录技术学习过程，不记录个人求职、入职安排或私人资料链接。

## 长期练习原则

### 1. 母题优先

不追求题量，优先掌握能够迁移到一类问题的典型题：

- 哈希表
- 双指针与快慢指针
- 滑动窗口
- 链表
- 栈与队列
- 二分查找
- 二叉树 BFS / DFS
- 网格 DFS / BFS 与泛洪思想
- 回溯
- 前缀和
- 区间问题
- 基础动态规划
- 堆
- LRU
- Promise 异步并发控制

### 2. 以独立写出为完成标准

看懂答案不等于掌握。每道题至少应经历：

1. 自己复述问题和边界条件。
2. 说清楚采用的数据结构或算法模板。
3. 用 TypeScript 独立写出。
4. 手动检查典型输入、空输入和边界输入。
5. 能说明时间复杂度和空间复杂度。

### 3. 控制重复练习

重复的目的应是验证能否独立写出，而不是机械重刷。优先补齐尚未覆盖的母题；已练过两次且能稳定写出的题，只在遗忘或面试前复习。

### 4. 保持适合面试的规模

练习目标是适应一小时面试中约 15～20 分钟的编程环节。优先选择能在这个时间内讲清思路并写出主体代码的初级、中级高频题，不为追求难度持续扩张题单。

## 建议的单次练习流程

每周日安排 2 道题，建议控制在 45～60 分钟：

1. 第一题复习一个已经接触过、但尚未形成稳定模板的题型。
2. 第二题补充一个新的高频母题，或完成同一专题的下一步。
3. 每题先独立思考和手写，再检查答案。
4. 结束后只记录结论：题目、练习次数、是否独立完成、主要卡点、下次动作。
